## Prompt 1: Environment art pass (main task)

```
You are a developer on Fantasy World Simulator (Godot 4.7.2 .NET + C# simulation)
Repo: F:\Code\game-dev (GitHub lemonzx01/game-dev, branch main)

Before starting, read: AGENTS.md (team and workflow rules), docs/handoffs/T018-art.md (character art style to match),
tools/art/make_characters.py (how the 24 px characters are generated: auto outline, rim shading, palette),
Game/Presentation/MapRenderer.cs and Assets/CREDITS.md

## Task: T018-env, environment pixel art matching the new characters
Current state: the characters are new pixel art (24×24, dark outline, rim shading), but terrain, trees, bushes, crops,
the storage shed and farm plots are still the old placeholders (Game/Assets/Placeholders/*) and do not match.
Goal: make new environment art in the same style and wire it into the renderer.

Work required:
1. Write tools/art/make_environment.py (Python + Pillow, deterministic, no external images or downloads)
   that generates Game/Assets/Art/environment_*.png, for example:
   - 16×16 terrain tiles: grass (2–3 variants so it doesn't look tiled), forest floor, mountain/rock, snow,
     shallow water, deep water, farmland; edges between water and land (shore), at least the 4 sides
   - water shimmer of 2–3 frames (presentation only)
   - trees: oak and pine (about 24–32 px tall), stump, bush with berries and empty bush, growing crops and ripe crops
   - storage building at the town centre (about 32×32), humans and demons may use different colours (Faction is in SettlementView)
2. Change the environment parts of Game/Presentation/MapRenderer.cs to use the new sheet:
   BuildTerrain, Shore, DrawSettlements, the resource-node drawing in _Draw, and the tile/plant/storage constants
   - you may move this code into a new partial file, e.g. Game/Presentation/MapRenderer.Environment.cs
   - pick tile variants with a hash of the coordinates (stable, no random every frame)
   - keep pixels crisp (nearest filter, integer sizes)
3. Add rows for the new files to Assets/CREDITS.md (CC0 / project-owned, generated by the script)

## Strict file boundaries (Claude Code is working on T019 at the same time)
You may write ONLY:
  tools/art/make_environment.py, Game/Assets/Art/environment_* (+ .import),
  Game/Presentation/MapRenderer.cs (environment parts only) or a new MapRenderer.Environment.cs,
  Assets/CREDITS.md (add rows only), docs/handoffs/T018-env.md, docs/handoffs/T018-env*.png,
  your own entry in PROGRESS.md
You must NOT edit:
  Simulation/**, Tests/**, Data/**, Game/Integration/**,
  the character code in MapRenderer (UpdateMotion, SheetRow, SheetColumn, DrawCreature, Motion, DrawnAt),
  Game/Assets/Art/characters_24.png, tools/art/make_characters.py
If you need data the simulation does not provide yet (e.g. a new read model),
do not edit the simulation yourself; write it as a "Request" in your handoff instead

## Simulation invariants (do not break)
- The renderer only reads the simulation; it must not invent stock, houses, people or events that do not exist in the simulation
- Animation and visual variants are presentation only and must not affect StateHash

## Workflow
1. git fetch, then create a worktree from the latest main:
   git worktree add worktrees/T018-env-codex -b feat/T018-environment-art origin/main
2. Claim the task first: write docs/handoffs/T018-env.md with state IN_PROGRESS, agent, branch, and the files you will touch, then commit
3. Work and commit only on that branch. No force push, reset --hard, or deleting other people's branches or files
4. Check everything before merging:
   - dotnet build Game/Game.csproj -c Debug
   - "%USERPROFILE%\scoop\apps\godot-mono\current\godot-mono.console.exe" --headless --path Game --import
   - run all 4 acceptances; each must print PASS:
     godot-mono.console.exe --headless --path Game res://Tests/PresentationAcceptance.tscn   (T007_ACCEPTANCE_PASS)
     ... res://Tests/ObserverAcceptance.tscn  (T008_ACCEPTANCE_PASS)
     ... res://Tests/GodToolsAcceptance.tscn  (GODTOOLS_ACCEPTANCE_PASS)
     ... res://Tests/SettlementAcceptance.tscn (SETTLEMENT_ACCEPTANCE_PASS)
   - dotnet test Tests/Simulation.Tests -c Release -m:1  (must still pass everything; you did not touch the simulation)
   - look at a real in-game frame: godot-mono.console.exe --path Game --write-movie <dir>/f.png --fixed-fps 30 --quit-after 240 --resolution 1280x720
     then pick a frame and save it as docs/handoffs/T018-env.png (actually open the image and check it looks right; don't just assume)
5. Merge (the owner allows merging after a self-review, A009):
   git fetch; merge origin/main into your branch first; if there are conflicts in a shared file, keep both sides; rerun the tests
   then in F:\Code\game-dev: git merge --no-ff feat/T018-environment-art, update your own entry in PROGRESS.md,
   git push origin main feat/T018-environment-art (if the push is rejected because main moved: fetch, merge, test again, then push; never force)
6. Update the handoff to DONE with: real commands and their results, the image, and what is still unfinished
7. Report to the owner in Thai: what you did, which files you touched, the test results, and the frame image
```
