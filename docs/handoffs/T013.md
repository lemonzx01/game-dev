## Design (ARCHITECTURE §9)
- **Format v1:** `"FWSSAVE\0"` magic, format version, state schema (= StateHash schema, one shared constant), options as JSON (config identity: seed, map/override, capacities, calendar, resources, vitals, mind, species table, ecology, psyche, grants, so a save is self-contained), binary payload, SHA-256 over options + payload, and the StateHash at capture.
- **Payload, in order:** tick and all counters (command sequence, entity id, memory id, carcass token, scheduler position); every RNG stream state; retained event log; accepted command queue (full issuer/mode/payload, target tick, sequence, in order); all scheduled work (keys, items, tokens, queue); terrain; resource amounts/regrow flags; every entity (vitals anchor, death booking, life cycle, mind incl. path/tokens/cooldowns, psyche incl. memories and relationships); death records; durable milestones; path request queue; carcasses. The spatial grid and map view are rebuilt.
- **Load** (`SimulationWorld.Load`) builds a separate world from the saved options, restores the payload with range/order/reference checks (IDs ascending below NextEntityId, queue targets = tick + 1, contiguous event log, milestones strictly before NextEventSequence, nonnegative resources ≤ capacity, valid vitals, paths and carcasses), then requires the recomputed StateHash to equal the saved one. Anything else throws `SaveFormatException`; the running world is never touched.
- **N2:** milestones (births, deaths) and death summaries live inside the checkpoint, so loading A cannot show events recorded after A. There is no separate archive file and no file I/O inside Step.
- **Files:** `SaveFiles.Write` writes `path.tmp`, flushes, verifies it loads, then `File.Replace` with `path.bak` (or a move for the first save). On failure the temp file is deleted and the previous save is untouched. `SaveFiles.Read` loads.

## Acceptance evidence (2026-11-24, Windows, SDK 10.0.404)
`dotnet test Tests/Simulation.Tests -c Release -m:1` → `62/62 test groups passed`, exit 0. T013 groups:
- Roundtrip: busy world (100 animals of 4 species with births, predation and deaths over 1,500 ticks, plus 2 accepted-but-unexecuted commands) → same StateHash, snapshot rows and calendar, retained events, history, entity details, minds (traits, fear, memories, relationships); saving the loaded world gives byte-identical bytes.
- Replay continuation: original and loaded world (with pending commands) stepped 600 ticks side by side → identical StateHash and event pages every tick.
- Malformed: wrong magic, unknown version, 6 truncation points, a flipped byte (checksum), edited tick, trailing data, edited tail data, broken options JSON and a swapped seed (all with valid checksums) → all `SaveFormatException`; the running world keeps stepping.
- N2: save A → entity starves → save B → load A shows no death and X alive; load B keeps the death; A stepped forward reproduces B exactly.
- Files: write, read back, second write keeps the first as `.bak`; a save that fails mid-write (wrong thread) leaves the previous file byte-identical and no `.tmp`.
